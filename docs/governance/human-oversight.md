# Human oversight

Draft for owner review (2026-11-26)

Who looks at what, how failures are found, and what a person can override. Nothing is deployed yet, so the production parts are plans. The rest describes the offline build and eval process in the ADRs.

## 1. Classification and what applies

- The [governance README](README.md) classes this demo as not high-risk under the EU AI Act. A Q&A demo over public documents is not on the high-risk list (check against source).
- **Art. 14 (human oversight)** applies to high-risk systems only. It is not a legal duty here. This note describes oversight anyway, because it is good practice and because NIST asks for it.
- **Art. 50 (transparency)** is the duty that applies. Visitors must be told they are talking to an AI system. That is the "answers are generated by AI" notice, control C15, **planned** for deployment ([control matrix](control-matrix.md)). Art. 50 also has rules on marking synthetic output. Whether those reach a plain-text Q&A answer is `TODO(owner): check against source`.
- **NIST AI RMF.** MAP 3.5 (processes for human oversight are defined) and GOVERN 3.2 (policies define the roles of people in human-AI configurations) are the nearest subcategories (check against source). This file is the proposed answer to both. It is not yet tagged in the [NIST crosswalk](nist-crosswalk.md), so the owner accepts the mapping there.

## 3. How failures are found in production

Question text is never logged ([ADR 0021](../decisions/0021-deployment-hosting-logging-and-review-owners.md), control C20). So there is no question log to read. What exists:

- **Aggregate counters.** `GET /stats` (bearer token, off when no token is set) returns requests, errors, "I don't know" answers, latency and today's spend ([`stats.py`](../../src/multimodal_doc_rag/stats.py), C27, planned until deployed). A change in the "I don't know" rate or the error rate is the main signal.
- **Provider spend.** The OpenRouter activity page for the production key ([deployment.md](../deployment.md)).
- **User reports.** The owner's contact route, and GitHub private vulnerability reports ([SECURITY.md](../../SECURITY.md)). `TODO(owner)`: put a "report a wrong answer" link beside the AI notice.
- **Citations.** Every answer shows the page, so a visitor can check it and report a mismatch ([C9](control-matrix.md)).
- **Periodic re-run.** `TODO(owner)`: decide whether to re-run the dev eval on a schedule. Not planned in any ADR.

What this cannot do: find out which real questions failed. The trade-off was accepted in ADR 0021.

## 4. What a person can override

| Who | What they can do |
|---|---|
| Visitor | Check the citation and the figure against the source page. Disregard the answer. There is no feedback button today |
| Owner, before release | Reject any gold item, refuse to review, or fail the release check. The check blocks on missing or thin evidence ([C36](control-matrix.md)) |
| Owner, in operation | Disable the production key, scale to zero, or lower the caps ([incident-response.md](incident-response.md)) |
| Nobody, per answer | No human sits in the loop on live answers. The system returns text and takes no actions ([C29](control-matrix.md)). That is why the output is a suggestion with checkable sources, not a decision |
