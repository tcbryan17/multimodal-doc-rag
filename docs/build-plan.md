# Build plan: a walking skeleton, test-first

Every step is one or more commits that are green on ruff, ruff format, mypy (strict) and pytest, locally and in CI. Each step lists what its tests prove and the concept to be able to explain afterwards. The reasoning lives in the ADRs (`docs/decisions/`); this file is just the order. Tick steps off as they land.

- [x] **0. Record decisions.** ADRs 0005–0013, README and CLAUDE.md.
- [x] **0b. FAA parser spike** (throwaway branch, not merged). Run PyMuPDF and Docling on two figure-heavy chapters. Measure the raster vs vector figure count, heading accuracy and caption pairing. Write the results and the choice into ADR 0006 *before step 4*, because the figure element shape depends on them.
- [x] **1. Quality gate.**
  - Set pytest `filterwarnings` (DeprecationWarning becomes an error) and register the `db` and `live` markers.
  - Add a pre-commit config (`uv run` system hooks).
  - Add a GitHub Actions workflow with a pgvector service container.
  - *Concept:* CI service containers vs the local compose container.
- [x] **2. The `/ask` contract.**
  - Add Pydantic request and response models.
  - Inject the pipeline **and the DB connection** as FastAPI dependencies.
  - Tests: the response shape, `ms >= 0`, and that `replay/sample-run.json` validates once it exists.
  - *Concept:* dependency injection, and the API as a contract.
- [x] **3. Migrations and schema.**
  - Write the runner and `0001_init.sql`.
  - Add a session fixture for the `rag_test` database, plus a fixture that rolls back each test.
  - Tests: migrations are idempotent; the tables and indexes exist; a vector round-trips.
  - *Concept:* migrations, and transactions as test isolation.
- [x] **4. Protocols, fakes and contract suites.**
  - Protocols: `Parser`, `Embedder`, `Reranker`, `Generator`, `FigureDescriber`.
  - Give each a trivial fake.
  - Write one contract suite per protocol, parametrised over its implementations.
  - *Concept:* contract tests make swapping a fake for the real thing checkable.
- [x] **5. The EDGAR parser,** tested on a hand-written `tests/fixtures/mini_10k.html`.
  - Tests: page labels come from footers and page breaks; sections from Item headings; tables become Markdown.
  - *Concept:* HTML layout becoming document structure.
- [x] **6. The chunker.**
  - Tests: the size cap; tables stay whole, or repeat their header when split; page ranges across page breaks; context headers.
  - *Concept:* the chunk is both the retrieval unit and the citation unit.
- [x] **7. The indexer** (`db` tests).
  - Store documents, chunks and per-model embeddings.
  - Re-ingesting a file with the same hash does nothing.
  - *Concept:* keying embeddings by model allows comparisons without re-ingesting.
- [x] **8. Hybrid search.**
  - Write `rrf()` as a pure function.
  - `db` tests: full-text search finds an exact term; the corpus and doc filters work; fusion keeps results from both lists.
  - *Concept:* RRF, and why vectors and keywords cover each other's blind spots.
- [x] **9. Answering and the end-to-end test.**
  - Wrap retrieved passages in delimiters in the prompt.
  - Drop any citation that doesn't point to a retrieved passage.
  - Return "I don't know" when nothing is retrieved.
  - Record one trace step per stage.
  - **End-to-end test:** ingest the fixture, call `/ask`, and get a citation with the right page label. This completes the skeleton.
  - *Concept:* grounding, and checking citations rather than trusting them.
- [x] **10. The OpenRouter client and real adapters.** *(The live calls have never run: no key yet.)*
  - Embeddings (truncated and re-normalised), rerank with a fallback, and chat with images.
  - `MockTransport` tests check that every request sends `zdr: true` and `data_collection: "deny"`, plus errors and fallbacks.
  - Add an opt-in `live` smoke test.
  - *Concept:* testing an HTTP client without the network, and privacy enforced in code.
- [x] **11. Fetch scripts** for EDGAR filings and FAA chapters, downloading into `data/`.
  - Ask the owner what contact to put in the SEC User-Agent.
- [x] **12. The PDF path** (the parser chosen in 0b).
  - Test it against a fixture PDF.
  - Add figure cropping, the decorative-image rules, the figure-description step (faked in tests), `ingest_failures` and the ingest report.
- [x] **13. Figures end to end.**
  - Store figures and serve them at `GET /figures/{id}.png`.
  - Add `image_url` to citations.
  - Send figure images to the generator.
- [x] **14. Real ingest** of both corpora (a manual run). Review the ingest report.
  - [x] Tooling: `scripts/ingest_corpus.py` (dry run + cost estimate, preflight canary, `--replace`, `--retry-failures`, reports in `reports/ingest/`), and a fail-closed spending cap (`models/cost.py`).
  - [x] Parsers validated on the real corpus without model calls (see the dry-run report).
  - [x] The owner adds the OpenRouter key; run the preflight, then the ingest. 25 documents; 139 of 496 figures first degraded (hidden reasoning used up the output cap, ADR 0015); after the fix and `--retry-failures`, 493 are described and 3 stay caption-only (provider errors mid-reply). Total spend about $0.25.
- [ ] **15. Eval harness.**
  - [x] Gold-set schema, metric functions (unit-tested), LLM judge, a runner with a cost cap that writes reports, drafting + review tools, injection sets, the eval-only index, judge calibration. See `evals/README.md`.
  - [x] The owner picks `JUDGE_MODEL`: `openai/gpt-6-luna` (ADR 0014).
  - [x] **Governance first (ADR 0016):** the release gates are pre-registered in `evals/gates.toml` *before* any gold item or score exists. `evals/gates.py` checks them, every eval report shows them as guidance, and `scripts/release_check.py` gives the binding verdict. Also written: `docs/governance/data-card.md`.
    - *Concept:* pre-registration. A threshold set after seeing the score describes the result; it doesn't test it.
  - [x] **Eval validity (ADR 0017),** before the gold set: the judge is sent the figure images the generator saw (and the hand-grader is shown them); binding runs search every document; evidence minimums in `gates.toml`; injection runs must match the final run's system; tooling for the embedder, chunk-size and figure-image comparisons (`scripts/embed_missing.py`, `scripts/make_chunk_index.py`, `run_eval.py --no-figure-images`).
    - *Concept:* construct validity. A metric can be computed correctly and still not measure what its name says.
  - [ ] The owner builds the gold set (after the ingest). Dev drafts are done (ADR 0018): 48 FAA and 60 10-K, waiting for review, plus 12 owner-written FAA figure questions. Held-out drafts still to come.
  - [ ] Judged smoke run, then the dev baseline. Once the baseline exists, `gates.toml` is frozen.
  - [ ] Injection runs (direct on `rag`, indirect on `rag_eval`) and judge calibration (about 30 hand grades).
  - [ ] Eval comparisons on dev (ADR 0011), checked against the gate table. The LLM-written context header comparison is deferred (ADR 0017).
- [x] **16. Replay file.** Needs only the key and the ingest, not the gold set, so it comes before the eval. Save one real response as `replay/sample-run.json`. The test from step 2 then validates it.
  - [x] Tooling: `scripts/save_replay.py` (inlines figures as data URIs, writes `sample-run.meta.json` with the question).
  - [x] Recorded: "What is the standard temperature at 5,000 feet?", answered from the Standard Atmosphere table images. `scripts/export_site_replay.py` turns it into the portfolio site's replay events.

- [ ] **17. Governance alongside the eval** (ADR 0016), in `docs/governance/`:
  - [ ] **Control matrix:** control → NIST AI RMF function / OWASP LLM 2026 risk → enforcing code → test or report → *implemented* or *planned*. Never mark a deployment control implemented before it exists.
  - [ ] **Risk register:** hallucination, prompt injection (direct and indirect), figure misreading, stale filings, cost abuse, privacy of live queries, provider outage. Each with likelihood, impact, mitigation and status.
  - *Concept:* evidence-backed controls. Every claim points to a test or a committed report.
- [ ] **18. The held-out final run and the release check.**
  - Run the held-out split once (`--i-know-this-is-heldout`), then `scripts/release_check.py` with the final, injection and calibration evidence. Commit the release-check report, pass or fail.
  - Write the **system card**: intended and out-of-scope use, models, gate results with CIs, limitations.
  - *Concept:* a release decision is a check that can fail, not a judgement call after the fact.
- [ ] **19. Deployment** (the owner decides: Postgres host, app hosting).
  - It ships only if `release_check.py` exits 0 (a required CI step).
  - Live-ops governance: question-log policy (whether to log, retention, no personal data in logs), monitoring (cost per day, error and "I don't know" rates), incident response.
  - Hardening: per-IP rate limits, input and output caps, a read-only DB role, a non-root container.
  - The EU AI Act Art. 50 "answers are AI-generated" notice in the UI.
